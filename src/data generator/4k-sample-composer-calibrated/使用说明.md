# 标注校准版：使用原 PNG，生成时直接输出正确规范的框

此文件夹是独立版本。原来的 `../4k-sample-composer` 和 `../objects` 均未修改。没有生成或覆盖任何修图版 PNG。

## 使用方法

1. 用 Chrome 或 Edge 打开本文件夹的 **dist/index.html**，完整保留 dist 中其他文件，不要只复制 HTML。
2. 导入 3840×2160 背景。
3. 从原 `../objects` 文件夹选择 16 张 PNG，素材上限已由 15 调到 16。页面应显示 **已校准 16/16 个素材**。
4. 像以前一样添加物体、移动、旋转、缩放。预览中的轴对齐框就是将导出的标注框；旋转控制虚线仍表示 PNG 的画布边缘，二者不同是正常现象。
5. 导出 PNG、JSON 或 ZIP。样本图片不画入标注框；JSON 的 bbox 使用校准后的参考框随物体变换得到。

不需要手工加透明边距，不需要重新抠图。原 PNG 像素保持不变。素材校准信息包含在 dist/sprite-box-calibration.js 和同名 JSON 中，应用离线读取 JS。

## “一致”的含义

一致指：该素材对应的原始标注框经过同样的平移、旋转和缩放后，生成其轴对齐框。不是每张新图里的同一类框都固定为某个像素大小。

例如 medium_launcher 的 PNG 是 24×25 像素，但其原标注框在 PNG 局部坐标中是 [-17,-11,31,35]，对应 48×46。旧版只按 24×25 的 PNG 矩形标框；新版使用 48×46 的参考框，同时保留不对称留边导致的位置差异。旋转后宽高会相应改变，中心也不强制等于 PNG 中心。

某些原框并不完全包住 PNG 矩形，例如 ta-ta 的一条原框边在 PNG 内侧；单靠加透明边距无法精确重现。这里使用参考坐标，不裁掉物体像素，也不增加伪装成物体的透明/近透明点。

## 校验与边界

- 16 个 PNG 的不透明像素已再次逐像素与原帧对应区域核验，原标注框也与对应 annotation 核对。
- 按 PNG 文件 SHA256 识别素材，改文件名仍可识别；同名但内容改变的 PNG 会拒绝套用旧规则。重新保存/编辑过的 PNG 需要重新核验，即使肉眼看起来一样。
- 未知的新 PNG 可以作为普通素材使用，但会明确计入“未校准”；它仍按 PNG 矩形标框，不能声称符合原规范。未来新素材按项目 ANNOTATION_CALIBRATION_WORKFLOW_ZH.md 校准。
- 校准文件缺失、浏览器不能核验文件或尺寸与记录不符时，不接受错误的校准导入。
- 超出 4K 图像的框按图像边界裁剪；完全无面积的框不导出。遮挡不自动扣除，不能据此保证重叠样本的标注语义正确。
- JSON 默认“标注框编辑”模式不改变原标注、不移动背景目标；导入 PNG 不会偷偷重标已有图像。
- “PNG 合成匹配”导入 JSON 只能按 bbox 放置零旋转实例，不能恢复旧 JSON 没有保存的旋转姿态。新代码按参考框的非对称偏移反算位置，保留 tank_1/tank_2 等独立实例。
- 校准只复用这 16 个原素材的参考规范，不保证参考框本身没有人工标注噪声，也不代表模型识别率必然提高。
